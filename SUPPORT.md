# Support

Crypta is an alpha-stage open source scaffold. Support is best-effort and not guaranteed.

## Asking Questions

Use GitHub issues or discussions for general questions that do not include sensitive information. Include enough context to understand your environment and goal.

## Reporting Bugs

Use the bug report issue template. Include:

- Clear description.
- Steps to reproduce.
- Expected behavior.
- Actual behavior.
- Environment details.
- Redacted logs or screenshots.

Do not include secrets, private keys, tokens, credentials, real user data, or vulnerability details in public issues.

## Requesting Features

Use the feature request issue template. Explain the problem, proposed solution, alternatives considered, and security/privacy impact.

## Reporting Security Issues

Do not report vulnerabilities publicly. Follow `SECURITY.md` for private disclosure.

## What Support Is Not Guaranteed

Maintainers do not guarantee:

- Production deployment support.
- Security incident response for third-party deployments.
- Custom integration work.
- Compatibility with every cloud, Kubernetes distribution, or mobile platform.
- Review of private forks.
- Recovery of lost keys, tokens, or data.
